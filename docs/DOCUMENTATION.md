# Documentation language

English is the default language for project documentation. Write new and substantially revised README files, guides, architecture notes, API contracts, specifications, change proposals, release notes, and code documentation in English.

Keep identifiers, commands, environment variables, routes, filenames, and user-interface strings accurate to the implementation. If a user-interface label is localized, quote the actual label when documenting a specific flow. Translation must not change the behavior described by a specification or an operational procedure.

Historical documents may retain their original wording until they are translated. When updating one, translate the edited document to English where practical. Keep links and anchors valid when headings change.
